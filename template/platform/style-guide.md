# 风格指南

所有 agent 共用的手艺知识。只存这一处：各 builder 的经验写进自己的章节，改动重要规则时在文末 Decisions 记一笔（日期 + 原因）。

## 1. 总原则

- **80/20**：约 80% 的内容能比较轻松看懂，约 20% 有些挑战（🧗 Stretch）。度量：课内小测正确率目标 75–85%，打卡难度感受约 3/5。连续高于 90% 就加难，低于 65% 就减难。
- **时间**：工作日每节课不超过 `learner/profile.md` 里的「每天时长」（没写就按 55 分钟，留 5 分钟缓冲）。Day 0 导览课 ≤30 分钟。宁可少讲一点，也不要超时。
- **一节课一个主线**：今天学完能做到/说清楚一件具体的事，写在 `lesson-goal` 里。
- **陌生领域先讲底层逻辑**：先建立"这东西为什么存在、解决什么问题、核心机制是什么"的直觉，再讲细节和工具。
- **防剧透**：课件不提未来某周会学什么。需要提前引用的概念用 🔭「后面会讲」，不写周数。
- **深挖拦截**：学习者容易在基础不够时急着深挖。课件里遇到"现在讲会跑偏"的点，用 🔭 一句话交代"是什么"，不展开。
- **不无聊**：每种内容选最合适的媒介，见第 3 节。但形式服务于理解，不为炫技。
- **不默认前置知识**：课里（正文、配音稿、组件、小测）用到的每个概念，要么学习者已经学过（`learner/concepts.md`）或背景里就有（`learner/profile.md`），要么当场用 1–2 句讲清；讲不清就换个说法或者不用。对照 profile 的背景判断：学习者在别的领域是行家，不代表懂这个领域"人人都知道"的常识（例如有数据分析背景、没写过软件的人，async、模块、服务器、HTTP 都要讲）。planner 在 spec 的「前置知识」里逐条标明处理方式，reviewer 逐条检查。
- **先猜再看**：每个主要段落和每个交互组件之前，先给一道先猜题（id `p1`、`p2`…），再给讲解。猜错是预期的：先猜题不进 `concepts.md`，不计入正确率（不放进 build.json 的 `quiz` 映射）。交互组件的初始画面不揭晓先猜题的答案。页面会自动标「先猜」、不占小测编号，猜错时显示中性的提示；lesson.js 和 events.mjs 靠 id 识别先猜题，所以 id 一定是 `p` 加数字，题干不用再以「先猜：」开头。
- **延迟检索**：热身 3 道题（`w1`–`w3`）：前一天的核心概念 + 两个更早学过的概念（包括 Day 0），让每个概念隔几天再被提取一次。课内当场的正确率只反映当下表现，隔几天还答得对才算学会。
- **讲给老师听**：课末打卡里有一题"用自己的话讲这节课最重要的是什么"（lesson.js 统一生成，`/today` 第二天回应）。writer 不用在课末另写"用一句话总结"之类的题。
- **做题只给提示**：「问老师」面板遇到小测、先猜题、热身题和练习，只给提示（规则在 `platform/ask-teacher.md`）。题干里的信息要足够让学习者靠提示自己想出来。
- **手写练习练逻辑，不练默写语法**（周末动手、学习者自己写的代码）：① 附一张语法速查卡，只列这次会用到的写法，和学习者熟悉的语言对照着写；② 学习者手写的只留做决定的部分（核心 20–30 行），import、类型声明、打印这类样板代码提前写好；③ README 写明：语法卡住先查卡，再问老师要写法，不算求助（规则见 CLAUDE.md「做题只给提示」）。动手练习的时间应该花在做决定上，不是想语法。
- **并行自测**：生成时多个 agent 同时跑 `tools/qa.mjs`，自测都用 `--out` 指向自己的目录（否则整页 QA 会清掉 `.tmp/qa/` 下别人的截图）。`qa.mjs` 用 `.tmp/qa.lock` 排队，一次只开一个 headless 浏览器。不要停止或 kill 本地服务器：别的 agent 和学习者也在用（自测结束时 kill 了服务器，正在跑的审核会断开连接）。服务器没开时 `qa.mjs` 会自己在后台启动它，不用你管。
- **命令行**：白名单（`.claude/settings.json`）以外的命令，每条都要学习者点一次确认；生成一周要几个小时，别让学习者一直守着。看、找、改文件用 Read、Glob、Grep、Edit、Write（改很多处就多次 Edit，或者用 `replace_all`），不用 ls、wc、sed 看或改文件，也不用 perl、python、`node -e` 写一次性脚本；Bash 只跑 `node tools/…`，命令前不加 `PORT=` 之类的环境变量（工具自己会读 `.env`，加了白名单就匹配不上）；不用 `sleep` 等待（`qa.mjs` 自己会排队）。课程内容要求实际运行的命令（第 5 节「报错栈、日志、命令输出要实际运行得到」）照常跑，尽量合并成一条。
- **源码里的转义**：Write、Edit、Bash 的输入里，`\uXXXX` 这类转义会被直接换成字符。要在文件里留下转义原文，用 `String.fromCharCode(92)` 拼出反斜杠，写完 grep 核对一遍。

## 2. 时长模型

估时写进每段的 `data-min`，各段之和就是整节课的预计时长（页面顶部和 hub 会显示）。

| 内容 | 估时 |
|---|---|
| 中文技术正文 | 约 300 字/分钟（含理解）；代码按每 10 行 1 分钟，没学过的语言每 10 行 2 分钟 |
| 配音动画 | 音频时长 × 1.3（暂停、回看） |
| 交互组件 | 每个 2–5 分钟，按验收标准里要做的操作估 |
| 选择题 | 每题 1 分钟；考还没学过的概念（诊断题）每题 2 分钟 |
| 回想题（reveal） | 每题 2 分钟 |
| 回顾热身 | 3–5 分钟（Day 0 和每个主题的第一节没有） |

- 最后乘以 `learner/profile.md` 里的 `pace_factor`（实际用时 ÷ 预计用时，由每周复盘更新）。`data-min` 已经乘过 pace_factor，所以 `events.mjs` 汇总里的"实际÷预计"是在当前 pace_factor 之上的修正：更新时用"当前 pace_factor × 这个比值"，不能直接拿比值当新的 pace_factor。
- 🧗 Stretch 段约占总时长 20%。
- 配音动画总时长不超过整节课的 40%。

实测（随使用积累，每周复盘时据此调整上表）：
- 暂无。

## 3. 媒介选择

| 适合 | 媒介 |
|---|---|
| 定义、论证、对比、清单、可以快速扫读的东西 | **文字**：读得最快，默认选它 |
| 过程、时序、数据流、架构、"一步步发生"的东西 | **配音动画**（`<lh-media>`）：每个 1–3 分钟 |
| 需要"手感"的参数、规律、反直觉的现象 | **交互组件**（`<lh-viz>`）：让学习者自己动手改、自己发现 |
| 空间结构、多维关系 | 2D 优先；只有 3D 真的帮助理解时才用 3D |
| 检验和巩固 | 小测：选择题检验理解，回想题做主动回忆 |

- 文字能讲清楚的，不要做成动画。
- 每节课通常 1–2 个配音动画 + 1–2 个交互组件，具体由 spec 决定。
- **交互组件要给出文字给不了的东西**：动手之后发现一个反直觉的结果，或者获得一种"原来如此"的手感。一句话就能懂的道理（学习者可能已经懂了）不做交互，省下的时间给别的内容。spec 的 viz 任务要写清楚"学习者动手后会发现什么"（可靠性组件"没有带来额外的理解，也没有眼前一亮的感觉"）。

## 4. 课程页结构（writer 的契约，lesson.js 依赖它）

```html
<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>课程标题</title>
<link rel="stylesheet" href="/assets/lesson.css">
<script type="module" src="/assets/lesson.js"></script>
</head>
<body>
<main class="lesson">
  <header class="lesson-head">
    <p class="lesson-when">第 1 周，周二</p>
    <h1>课程标题：具体、有信息量</h1>
    <p class="lesson-goal">学完今天，你能……（一两句）</p>
  </header>

  <section data-sec="warmup" data-min="4">
    <h2>回顾热身</h2>
    <lh-quiz id="w1" type="reveal">
      <p>回想题</p>
      <div class="why"><p>参考答案</p></div>
    </lh-quiz>
  </section>

  <section data-sec="core-1" data-min="10">
    <h2>段落标题</h2>
    <aside class="later"><p>Embedding：把文字变成一串数字，用来比较意思是否相近。</p></aside>
    <p>正文……<mark>本段最该记住的一句话</mark>……第一次出现的术语用 <dfn>Token</dfn>。</p>
    <lh-media id="flow" title="一次请求的完整旅程"></lh-media>
    <lh-viz id="token-cost" title="算一算 Token 成本" hint="拖动滑块，看看……" height="460"></lh-viz>
    <p class="takeaway">一句话总结：……</p>
  </section>

  <section data-sec="stretch-1" data-min="8" data-stretch="可选：自定义的 Stretch 提示语">
    <h2>……</h2>
  </section>

  <section data-sec="check" data-min="4">
    <h2>小测</h2>
    <lh-quiz id="q1" answer="b">
      <p>题干</p>
      <ul>
        <li data-k="a">选项</li>
        <li data-k="b">选项</li>
        <li data-k="c">选项</li>
      </ul>
      <div class="why"><p>解析：为什么 b 对，其它为什么错</p></div>
    </lh-quiz>
  </section>

  <lh-checkin></lh-checkin>
</main>
</body>
</html>
```

| 元素 | 规则 |
|---|---|
| `section[data-sec][data-min]` | 必须是 `main` 的直接子元素。`data-sec` 在页内唯一（小写字母、数字、连字符）；`data-min` 是整数分钟。lesson.js 会自动加编号、分钟数，并生成今日路线。 |
| `h2` | 每段一个，写段落标题，不要自己加编号 |
| `data-stretch` | 标在整段上。值可以留空（用默认提示语），也可以写一句定制提示 |
| `aside.later` | 🔭 后面会讲。**写在它所注释的段落之前**（显示在该段右侧）。一句话说清"是什么"，不写什么时候讲、不展开 |
| `aside` | 灰色页边注：补充说明、出处、类比。跳过不影响理解 |
| `mark` | 荧光笔，每段最多一处 |
| `dfn` | 术语第一次出现 |
| `p.takeaway` | 一句话总结，每段最多一个，可省略 |
| `<lh-media id title>` | 配音动画插槽，对应 `media/<id>/`。id 由 spec 指定，writer 不能自己编 |
| `<lh-viz id title hint height [wide]>` | 交互组件插槽，对应 `viz/<id>.html`。`height` 是初始高度（加载后自动适配内容）；`wide` 让组件延伸到页边栏 |
| `<lh-quiz id answer>` | 选择题：`ul > li[data-k]` 列出选项，`answer` 是正确选项的 `data-k`，`.why` 写解析。诊断题（考还没学过的概念）可以加一项 `<li data-k="x">还不确定</li>`：选了不算答错，页面显示中性的提示，事件里记 `unsure: true` |
| `<lh-quiz id type="reveal">` | 回想题：题干 + `.why` 参考答案。学习者先想，再看答案，然后自评 |
| `<lh-checkin>` | 课末打卡，放在 `main` 最后（后面只能跟回看快照）。表单由 lesson.js 生成 |
| `<lh-recall ref>` | 回指回看：包住回指的那几个字，`ref` 指向之前学过的一处内容。快照 `<template data-recall>` 放在 `<lh-checkin>` 后面。见下面「回指回看」 |
| `pre > code`、`table` | 正常写，代码块自动加复制按钮 |

不要写：自己的 CSS 或 JS（版式统一由 lesson.css/lesson.js 负责）、外部资源、emoji 装饰（🔭 🧗 由系统加）。

### 代码片段的出处和行号（`<pre data-src data-lines>`）

摘自真实文件的代码块（比如学习者自己项目里的文件），标出文件名，左边显示它在原文件里的行号，学习者对得上课文说的「第 N 行」：

```html
<pre id="serve-static" data-src="tools/serve.mjs" data-lines="70-78,90-95"><code>…</code></pre>
```

- `data-src`：文件的路径，显示在代码块顶上。
- `data-lines`：按片段里的顺序写原文件的行号段，逗号分开（`70-78`；单独一行写 `92`）。`/assets/lh-lines.js` 给片段的每一行依次编号，显示在左边的行号栏里；复制按钮不带行号。
- 中间省略的地方单独一行写省略号：`…`、`// …`，或者 `// …… 中间省略了什么`。这一行不编号，前后的行号跳过去。不写省略号也行，行号照样跳。
- 原文件的一长行在片段里折成几行时，这一行的行号重复写（`134-137,137,138`），折出来的行不显示行号。
- 摘的行可以缩短（行中间用 `…`）、行末可以加讲解注释，仍算原文件的那一行；不能插入原文件没有的行、不能调换顺序。要这样改写，就不加这两个属性，课文里也别按行号引用这一段。
- 片段的行数（不算省略号行）和 `data-lines` 的总行数对不上时不显示行号（文件名照样显示），QA 报错（快照里的代码块也查）。
- 课文里说的「第 N 行」要落在片段显示的行号里。源文件改了、行号挪动后，课文和 `data-lines` 一起改。
- 不是摘自真实文件的代码不加：AI 写的示例、改写过的简化版、终端输出、HTTP 报文、`git diff` 输出。
- 回指快照原样拷贝代码块时带着这两个属性，小窗里也显示文件名和行号。

### 回指回看（`<lh-recall>`）

课文提到之前学过的一处具体内容时（**回指**），在那几个字上加回看：学习者点开小窗就能看到当时的原文，不用去翻旧课。小窗平常收起，先靠自己的记忆回想；需要时再点。

**什么算回指**：正文、题干、解析里明确指向之前某节课里**一处具体内容**的说法：
- 一道题：「Day 0 诊断第 4 题」「Day 0 那道 429 的题」
- 一段讲解（段落、代码块、表格）：「Day 0 说的静默出错」「Day 0 读过的那段代码」「昨天说过」
- 学习者写下的话（打卡、「这里没懂」、问老师）：「Day 0 你问过 serve.mjs 是做什么的」
- 配音动画、交互组件：「昨天的动画说」

不算：只说"来自 Day 0"、不落到具体一处的（热身的引导语）；同一页里的前后指（"上一段""开头那道先猜题"）；题目考的是旧内容、但题干没提旧课的。

**规则**
- 只能指向已经学过的课（比当前页早的周和天）。
- 每处回指都加，同一个 ref 可以在一页里出现多次。触发文字就是回指的那几个字，不超过约 15 个字（窄屏上一个回指不能比一行长）。
- **热身题的题干里不加**：热身本身就是回想练习，题干上能点开原文，学习者会直接去看、跳过回想。改在 `.why`（答案展开区）末尾加一行 `<p>对照原文：<lh-recall ref="…">…</lh-recall></p>`。先猜题和其他小测的题干可以加：先猜不计分；题目类的回看还要再点「看答案」才显示答案。
- 指向的元素要有 id：小测本来就有；段落、代码块、表格在原课上补一个 id（小写字母、数字、连字符，页内唯一），只加 id，不改别的。被引用的元素里不要嵌套同名标签（检查工具按 id 找元素时更简单）。
- 原文不在课程页上的（学习者的留言），锚点写它所在段落的 `data-sec`，打卡写 `checkin`。
- 回指的说法要和原文对得上：比如原文是「这里没懂」，课文就不要写成"打卡里你说"。
- 回指后面紧跟标点（右括号、句号）时，「回看」小标记容易把标点挤到下一行开头。尽量把回指放在句子中间，写完看一眼截图。
- 回想题（reveal）的题干点名旧课某个概念、点开原文就等于看到答案时，和热身题一样把回看放进 `.why` 末尾的「对照原文」。
- 回指同一周前几天的课时，那几页可能还在生成或修复轮里：等那一页稳定后再取快照；生成结束前由主会话把整周快照和原文再比对一遍。被别的课引用的元素（带 id），修复时尽量不改它的文字；要补充就加页边注或新段落。

**写法**

正文里：

```html
<p><lh-recall ref="w00/d0#q4">Day 0 诊断第 4 题</lh-recall>，你选了……</p>
```

`ref` = `wNN/dN#锚点`（同一门课；锚点是元素 id、段落的 `data-sec` 或 `checkin`）。同一个锚点上有两条不同的留言都被引用时，第二条写 `#diagnostic~2`：`~` 后面只用来区分快照，跳转时忽略。

快照：每个 ref 一份，放在 `<lh-checkin>` 后面、`</main>` 前面：

```html
<!-- 回看快照：正文里 <lh-recall ref> 指向的原文，生成时原样拷贝 -->
<template data-recall="w00/d0#q4" data-kind="quiz" data-label="Day 0 · 起点诊断 第 4 题" data-was="a">
<lh-quiz id="q4" answer="c">……原样拷贝……</lh-quiz>
</template>
<template data-recall="w00/d0#diagnostic" data-kind="note" data-label="Day 0 · 起点诊断" data-src="capture" data-at="2026-01-05T20:30:00+08:00" data-field="note">
<blockquote>学习者的原话</blockquote>
</template>
```

| 属性 | 说明 |
|---|---|
| `data-recall` | 和正文的 `ref` 一字不差 |
| `data-kind` | `quiz` 题，`text` 讲解（段落、代码块、表格……），`note` 学习者写下的话，`media` 配音动画，`viz` 交互组件 |
| `data-label` | 小窗标题：哪节课 · 哪一段或第几题，如 `Day 0 · 起点诊断 第 4 题`、`W1 周一 · 段落标题` |
| `data-was` | 只给 `quiz`：学习者当时的作答。选择题写选项的 `data-k`；回想题写自评 `got` / `partial` / `missed`（当时写的想法放 `data-was-note`）；那节课打过卡、这题却没有作答记录的写 `skip`（小窗显示"当时跳过了"）；学习记录里找不到的不写：小窗会再看原页面在这个浏览器里存的作答，都没有就显示"没找到当时的作答"。不笼统地写"未作答" |
| `data-src` `data-at` `data-field` | 只给 `note`：事件类型（`checkin`、`capture`、`ask`），那条事件的 `ts`（原样拷贝），哪个字段（`unclear`、`note`、`explain`、`question`……） |

模板里放什么：
- `quiz`、`text`、`media`、`viz`：原文元素的 outerHTML，**原样拷贝**（包括 id 和其他属性）。
- `note`：`<blockquote>` 里放学习者的原话，`&`、`<`、`>` 写成实体，错字也不改。

作答和留言从哪来：`node tools/events.mjs --answers lessons/<topic>/wNN/dN` 列出那节课每道题的第一次作答、打卡和留言，带 `ts`。

**比对快照和原文**（给检查工具：只读两边，不需要别的信息）：
- `quiz`、`text`、`media`、`viz`：原文 = `site/lessons/<topic>/wNN/dN/index.html` 里 id 等于锚点的元素。两边的 outerHTML 各自规范化后应该相等。规范化：连续空白压成一个空格，去掉 `>` 和 `<` 之间的空格，去掉首尾空白。
- `note`：原文 = `learner/events.jsonl` 里 `page` 是那节课、`type` = `data-src`、`ts` = `data-at` 的那条事件的 `data-field` 字段；和 `blockquote` 的文字（实体还原后）规范化后比较。
- 对不上时，小窗照旧显示快照，也就是学习者当时学的那一版。由生成或调整课件的 agent 按实际文本在新版里找对应内容，判断要不要更新快照；不在打开小窗时临时去找。

**运行时**（`/assets/lh-recall.js`，lesson.js 加载）：回指显示成虚下划线加一个「回看」小标记，键盘能聚焦，点击区至少 44px 高。小窗是最上层的弹窗：题目先只显示题干和选项（点不动），点「看答案」才显示正确答案、学习者当时的作答和解析；讲解、留言直接显示；配音动画和交互组件只放一句说明。快照里嵌套的回指（被引用的原文自己也引用了更早的课）在小窗里显示成普通文字、点不开，要看就点「去原文」。代码块、表格比小窗宽时，小窗放宽到放得下为止，最多 760px；窄屏放不下就在框里横向滚动，右边缘有阴影提示。留言和当时写的想法照原样保留换行和缩进。小窗底部的「去原文」在新标签页打开旧课的 `?from=recall#锚点`：那一页只读（不计时，不记进度、作答和打卡），停在锚点上并短暂标出。Esc 或点外面关小窗，焦点回到回指处；点「暂停」「犯困了」时先关小窗。每次点开记一条 `recall_open`（`ref`、`kind`、所在段），`tools/events.mjs` 的汇总里有"回看 N 次"。QA 会对没有快照的回指、没被引用的快照、ref 写法不对、指向当前或之后的课报警告。

**视觉主题**：课件 HTML 和视觉无关。外观由这门课的主题决定（`site/manifest.json` 的 `topics.<topic>.theme`），主题在 `site/assets/themes/<名字>/`，规范见 `site/assets/themes/README.md`。现有三个：`quest`（工程/编程）、`ink`（文科）、`anatomy`（数学/金融/理论）。所以正文不写界面的颜色和位置（见第 5 节）。

## 5. writer 章节

- **语气**：像一个耐心、讲话具体的工程师朋友。少用形容词和套话（"首先""总之""值得注意的是"），不用感叹号。
- **结构**：先给例子或直觉，再给定义。一段只讲一个意思，段落不超过 5 行。
- **排版**：中文和英文、数字之间加空格；用全角标点。术语第一次出现写"中文（English）"，之后可以直接用英文。
- **热身**：题目来自 spec（planner 根据 `learner/concepts.md` 里到期和模糊的概念给出），不自己编。
- **🔭**：只给 spec 里列出的前向提示。正文里不写"下周""以后我们会学"。
- **结尾**：最后一段内容之后直接放小测和打卡，不写大段总结。
- **小测**：干扰项要像真的会犯的错误，不要明显荒谬。解析说清为什么错。

经验（随使用积累）：
- 表格每行各列的最长内容加起来控制在约 39 个汉字以内（正文栏 36rem、表格 15px），否则首列会被挤成逐字换行；放不下就改成列表。
- 选择题轮换正确选项的位置，正确选项不要明显比干扰项长；解释放进解析，不放进选项。写完把四个选项的字数并排比一次。
- 引用仓库里的真实代码时，打开源文件逐行核对，别凭 spec 的转述写注释和答案（spec 里的返回值和代码实际不一致）。代码里出现的每个函数名和路由都用一句话交代它是什么，包括正文和表格没提到的（`/api/exists`）。
- 正文不写界面元素的颜色和位置（如"页边蓝色的 🔭""右下角三个按钮"），用名字称呼（"🔭 后面会讲""「这里没懂」按钮"）。视觉换了，正文还成立。
- 带 `--参数` 的长命令不放页边注：页边栏窄，会在连字符处断开。放正文或代码块。正文里逐个解释参数时，改成每条以参数开头的列表项。
- 行内代码里的 Windows 路径（如 `…\项目文件夹\…`）会在 "…" 后面断行，在 "…" 后面加 `&#8288;`。
- 报错栈、日志、命令输出要实际运行得到，不凭记忆或 spec 的预期写：在仓库外的副本里跑（serve.mjs 的副本放在 `<临时目录>/tools/` 下，ROOT/site 才对得上），用别的端口，不碰 4321。真实输出常比预期多一行 `node:internal`，列号也可能不同。
- spec 里写的代码行数、示例数据和先猜题的设定可能对不上：行数用 `wc -l` 核对，示例的说明文字跟着示例走，不照抄 spec 的标签。
- 小测解析（`.why`）里不用 `dfn`：lesson.js 会把 `dfn` 收进页首「本课图鉴」，学习者答题前就看到了。
- 页边注（包括 🔭）放在它注释的那句话**所在段落**的正前面。几条注连着放时会浮到前一段旁边，读者对不上。
- 给学习者的安装和运行命令，要在仓库外的干净目录实测：在仓库子目录里 `npm install` 会装进上层的 package.json；npm 11 的 `npm init -y` 会写 `"type": "commonjs"`，ES 模块写法会直接报错。
- 句子的主语和动作要对得上，别让学习者猜"是谁做的"。"JSON.parse 返回 any……换成 unknown"没说是谁换、怎么换，学习者分不清是函数自带还是代码写法造成的；"浏览器在页面里跑"应写成"代码在浏览器打开的页面里跑"。讲一个值的类型时，说清是函数声明的还是你在代码里标的。
- 按行号引用仓库代码时，同时写出函数名或那一行的特征，行号只作辅助。平台 PR 改了被引用的文件后，已生成的课程页里的行号会过期，要重新核对。核对时把这一页引用的所有行号都对一遍，不只看被报出来的那几处。
- 题干里超过约 30 个字符的代码不用行内代码，改成代码块：行内代码会在空格处断成两行。短的也一样：带空格的行内代码碰到行尾就会断开，题干里要对比两段代码时一律用代码块。
- 拿学习者熟悉的语言或领域做对照（`A ≈ B`），只在学习者真的认识 B 时才有用：会一门语言不等于用过它的标准库。写对照时补半句 B 做什么（例：`JSON.stringify(x) ≈ json.dumps(x)` 曾被点了「这里没懂」）。
- 课文的说法和展示的原文看起来矛盾时，要主动点破。例如课文说"这是一次 HTTPS POST"，展示的原文第一行却是 `HTTP/1.1`，Host 里也没有 https，学习者就会困惑。这里应该补一句：协议写在地址里，发请求之前就决定了，原文里不写。
- 关于 API 能做什么、不能做什么的绝对说法（"没有……""只能……"）最容易过时。写之前到官方功能页核对，不能只看 API 参考页的概述；planner 写 spec 的事实核查提示时同样适用（spec 和课文都写了过时的 system 角色说法，审核拦下）。
- spec 要求沿用之前某天的比喻或例子时，打开那天的课程页和配音稿核对实际用词，不照抄 spec 的转述：学习者记得的是课上的说法（spec 转述的比喻细节和周三课里的实际用词对不上）。

## 6. viz 章节（交互组件）

```html
<!doctype html>
<html lang="zh-CN">
<head>
<meta charset="utf-8">
<title>组件标题</title>
<link rel="stylesheet" href="/assets/component.css">
<!-- 需要 3D 时：
<script type="importmap">{ "imports": { "three": "/assets/vendor/three/three.module.js", "three/addons/": "/assets/vendor/three/addons/" } }</script> -->
</head>
<body>
  …
<script type="module">
import { emit } from '/assets/component.js';
…
</script>
</body>
</html>
```

- 每个组件一个文件 `viz/<id>.html`，能单独打开自测。必须加载 `component.css` 和 `component.js`。
- **高度由内容决定**：不要给 html/body 设 `height:100%`；画布类组件给容器写死高度（如 `.stage { height: 420px }`）。
- **打开就能看懂**：有合理的默认值，一句操作提示。不需要操作也能看到一个有意义的初始画面。
- **多步演示**：会一步步自动往下走、旁边的解说跟着换的演示（代码逐行执行、数据一站站传下去等），都要：
  - 能单步：「下一步」一次只走一步，解说停在这一步；
  - 能暂停：演示进行中主按钮是「暂停 / 继续」；
  - 留够读的时间：自动播放时，每一步按这一步解说的字数算时长，`1000 ms + 每字 100 ms`，夹在 2–7 秒（约每秒 8 字。第 2 节的中文技术正文是每秒 5 字，解说里夹着代码词、读得快些）；没有解说、只是画面在变的，每步至少 2 秒。嫌慢的学习者会按「下一步」自己走，太快只能暂停，所以宁慢勿快；
  - `prefers-reduced-motion` 时不自动走，直接给结果。

  只把格子逐个点亮、最后整张结果留在屏幕上的不算。
- **事件**：用户完成有意义的操作时 `emit('viz_<id>_xxx', {...})`，比如"找到了临界点"，不要每次拖动都发。
- **颜色和控件**：只用主题 token（`--paper --paper-2 --ink --pencil --rule --marker --pen --climb --red --screen --sans --mono`，契约见 `site/assets/themes/README.md`）和主题的默认控件样式，不写死颜色。图形的画法按这门课主题的 `DESIGN.md`，参考实现是 `site/lab/themes/<主题>/viz/`。
- **3D**：用本地的 three.js r186（importmap 如上），不用 CDN。整页的 WebGL 上下文（含配音动画）不超过 3 个。
- 不用 `alert/confirm/prompt`。键盘能操作，焦点可见。不加载外部资源。
- **自测**：`node tools/qa.mjs lessons/<topic>/wNN/dN` 看 `viz-<id>.png` 和报错。课程页还没写好时也能单独打开 `http://localhost:4321/lessons/.../viz/<id>.html`。

经验（随使用积累）：
- 要验证真实宽度、自动高度和 `emit` 事件：写一个同源的临时页面，把组件放进 648px 宽的 iframe，监听 `message`。单独打开组件时处于 QA 模式，事件不会上报。
- 会随状态变化长短的解读文字，给它留够最小高度（如两行），避免 iframe 高度跳动。
- 颜色之外再用形状区分状态（✓ × !），照顾色弱。× 不要放进旋转 45° 的菱形，小尺寸下会看成 ❖ 花纹：成功用菱形 + ✓，失败用圆形 + ×。
- 外层用 grid 时，给子元素加 `min-width: 0`（或 `grid-template-columns: minmax(0, 1fr)`），否则 `white-space: pre` 的代码块会在窄屏把组件撑出 iframe。
- 主题的 `component.css` 有全局的 `.ok`、`.bad` 文字色类。组件自己的状态类名加前缀（`is-ok`、`t-bad`），也别和组件里已有的状态类（如 `.chg`）重名。
- 检查"拖到同一时刻画面一样"时，比较可见状态，跳过 `hidden` 元素；直接比 innerHTML 会被隐藏元素里缓存的内容误报。
- 会发真实请求的组件：测试时只通过控件单次发送，不写脚本循环发 POST（auto 模式会拦）。Chrome 会把 fetch 收到的 4xx/5xx 自动记成控制台网络日志，这类组件的验收只看 JS 报错（`__LHC.errors`）。
- 实测高度和 spec 建议差得多时，在返回里写明实测高度，由主会话让 writer 改插槽的 `height`，避免加载时跳动（组件常比建议高 150–300px）。
- 组件里嵌仓库源码快照：放进 `<script type="application/json">`，把 `<` 转义成 `<`，免得源码里的 `</script>` 截断页面；生成脚本存到 `curriculum/<topic>/wNN/`，平台 PR 改了源文件、行号变了时可以重新生成。
- 几百个可聚焦的元素（如代码行号）用 roving tabindex：只有一个 `tabindex=0`，其余靠方向键移动。重画会换掉按钮时，用 `data-*` 记住焦点在哪个按钮上，画完放回去，否则键盘用户每点一下焦点就丢。
- `<button>` 默认把内容垂直居中：里面放会换行的代码时，加 `display:flex; align-items:flex-start`。
- 随状态变化、混排两种字体的数值行，用固定高度加 `align-items: center`，不用 baseline 对齐，否则换字体时差 1px，iframe 跟着跳。两栏组件里让其中一栏（如证据区）`flex: 1 1 0; min-height: …; overflow: auto`，吸收另一栏展开的高度。
- 模拟服务器端（Node）的 URL 解析时，不能直接用浏览器的 `new URL()`：Chromium 会把路径里的 `%2e` 还原成 `.`，Node 不会。按标准自己实现，并用 Node 对拍。
- SVG 滤镜（晕染、毛边）用 `filterUnits="userSpaceOnUse"` 并给足区域：默认的 objectBoundingBox 遇到水平或竖直的直线（外框高或宽为 0）时，整条线会消失。组件的 `component.css` 不加载书法字体，`--brush` 会退回楷体，书法字留给课程页和配音动画用。
- 多步演示的写法：拆成两层，`step()` 只走一步、换解说、重画；`tick()` 调一次 `step()`，再按 `readMs(这一步的解说)` 排下一次 `tick()`。「下一步」停掉计时器再调 `step()`，自动播放调 `tick()`，暂停就是清掉计时器。几百毫秒换一次解说，学习者读不完，还以为自己没看懂。

## 7. media 章节（配音动画）

目录 `media/<id>/`：`script.json` →（`node tools/tts.mjs`）→ `audio.mp3` + `timeline.json`，再写 `scene.html`。

**配音稿 `script.json`**

```json
{ "beats": [
  { "id": "hook", "text": "字幕和配音文本", "pauseAfter": 0.4 },
  { "id": "api", "text": "调用 API 只要 3 步。", "say": "调用 A P I 只要三步。" }
] }
```

- 口语化、短句。每个 beat 1–3 句，对应画面上的一个变化。一个动画 60–180 秒。
- `say` 只送给 TTS：写数字、符号、英文缩写的读法。全局通用的读法加进 `platform/pronunciation.md`，不用每次写 `say`。
- 避免只有一两个字的 beat（ElevenLabs 偶尔会多读）。
- **声音**：`platform/tts.json` 里列出默认声音和语速。每个动画按路径自动随机用其中一个（稳定，重跑不会换）。不要在 `script.json` 里指定 `voice` 或 `speed`。没有配音 key 时 `tts.mjs` 自动改用静音（`silent`）：按字数估时长，播放器显示字幕，默认由浏览器朗读（读 `say`，没有就读 `text`）。浏览器读得比估算的慢时，画面停在句尾等它读完，所以动画照样锚定在 beat 上就能对上。
- **双人对话（可选）**：beat 加 `"speaker": "b"` 就由列表里的下一个声音来读（可能是一男一女，也可能是两个女声），字幕显示为黄色。适合提问与回答、"常见误解 vs 正确说法"、两种方案对比。台词要像两个人在说话（b 可以提问、插话、追问）。每节课最多一个对话式动画，不为了用而用。

**合成**：`node tools/tts.mjs site/lessons/<topic>/wNN/dN/media/<id>`。改稿后重跑只会重新合成改动过的 beat。出现 ⚠ 时长异常要处理：改写那个 beat 或用 `say`。

**场景 `scene.html`**：参考 `site/lab/themes/<主题>/media/one-request/scene.html`。

```html
<link rel="stylesheet" href="/assets/player.css">
<div id="stage"><svg viewBox="0 0 1280 720">…</svg></div>
<script type="module">
import { mountScene, ease, lerp, clamp } from '/assets/player.js';
mountScene({
  setup({ stage, ctx }) { /* 只执行一次 */ },
  seek(t, ctx) { /* 纯函数：把画面画成时刻 t 的样子 */ },
});
</script>
```

- `seek(t)` 必须是确定性的：同一个 t 永远画出同一帧，不依赖上一帧的状态。拖动、倍速、截图都依赖这一点。
- 动画锚定 beat，不写死秒数：`ctx.p('api', t, { at: 0.3, dur: 0.6 })`、`ctx.visible(t, 'api', 'next')`。
- t=0 的画面就是封面，要能独立成立（标题 + 一个视觉钩子）。
- **语音说到哪，画面亮到哪**：一次只强调一个元素，其余变暗。
- 舞台 1280×720。画面上的文字不小于 28 单位；底部 15% 留给字幕和控制条，不放重要内容。
- 舞台、配色和画法按这门课主题的 `DESIGN.md`，颜色和字体用主题 token（CSS 变量，SVG 里可以写 `fill="var(--ink)"`），不写死颜色。参考实现是 `site/lab/themes/<主题>/media/`。
- **自测**：`node tools/qa.mjs lessons/<topic>/wNN/dN`，逐张看 `media-<id>-*.png`（封面 + 每个 beat 70% 处）。

经验（随使用积累）：
- 3D 卡片上的文字要始终朝向镜头，转到背面会变成镜像。
- 要在 beat 中间对准某个短语：按字数权重换算时刻（汉字 1、英文词 1.6、数字 0.9、逗号 1.2、冒号 1.6、句号/问号 2.6 个字当量），对照 MiniMax 实际停顿平均误差约 0.3 秒、最大约 0.8 秒。需要精确对齐的画面变化，最好拆成单独的 beat。
- 移动中的带字卡片副本叠在原卡片上会很乱，改用不带字的小卡。
- 70% 处的 beat 截图看不到 beat 内部的运动；关键过渡（发送、返回、通过检查）要额外在 beat 中段截图检查。
- 字幕条实际从 y≈582 开始（不是 612），重要内容放在 y<575。
- 场景里的 `.mono` 加 `font-variant-ligatures: none`，否则 Cascadia Code 会把 `===`、`=>` 显示成连字。
- 封面用单独的足尺元素，播放后再变形到主画面的位置；把主画面整体缩小当封面，里面的文字会小于 28。
- 同一位置换文字：先淡出旧的，再淡入新的，不要交叉淡化（叠在一起会糊）；换字时刻避开 beat 的 70% 处，那是 QA 的截图点。
- 飞进核心对象的小卡片画在对象下面一层，到达时像"装进去"，不会盖住对象的文字。从半透明（被压暗）的物件后面穿过时卡片会透出来：在物件下面垫一块和舞台同色的不透明底板，卡片落点对准物件中部。
- 要圈出等宽代码里的某一个字符：用 SVG `<text>` 的 x 列表逐字定位（字宽取 0.6em），位置不受字体加载影响。
- 中文多音字（人名、文言词）在 `platform/pronunciation.md` 里用同音字替换（词表对汉字也生效，例如「温庭筠 → 温庭云」）；"得"（děi）这类口语多音字能换说法就换掉，免得读错。

## 8. reviewer 章节

**技术检查**：`node tools/qa.mjs lessons/<topic>/wNN/dN`，然后用 Read 看截图：整页、每段、每个配音动画的封面和每个 beat、每个交互组件。报告里的错误全部算阻塞。

**事实核查**：
- 有时效性的内容（模型名称、价格、上下文长度、API 参数、产品功能、版本号、"最新""目前"）用 WebSearch/WebFetch 核实官方来源，正文写明"截至 <当前年月>"。
- 核实不了的：改写成不依赖具体数字的说法，或删掉。
- 代码示例要能运行（至少语法正确、API 用法与当前文档一致）。

**教学检查**：
- 80/20：核心内容是否能轻松看懂；Stretch 是否约占 20%，并且标了出来。
- 时长：各段 `data-min` 之和 不超过 profile 的「每天时长」（默认 55；Day 0 ≤30）；按第 2 节的时长模型复算，偏差超过 15% 要指出。
- 无剧透：对照 spec 的"禁止提及"清单；没有"下周""第 N 周会学"。
- 🔭 是否恰当：该拦的拦了，没有在正文里展开。
- 前置知识：对照 spec 的「前置知识」和 `learner/profile.md` 的背景，正文、配音稿、组件、小测里有没有用到学习者没学过、也没当场讲清的概念（没解释就是应修，影响理解主线就是阻塞）。
- 小测：答案正确，干扰项合理，解析清楚。
- 回指回看（第 4 节「回指回看」）：正文、题干、解析里每一处回指都有 `<lh-recall>`（热身题题干除外，放在 `.why` 里）；每个 ref 能解析：指向更早的课，那一页上有这个 id（或 data-sec、checkin），且有对应的快照；快照和原文一致（按第 4 节的规范化比对；`data-was` 和学习记录一致，用 `events.mjs --answers` 核对）；回指的说法和原文对得上。缺回看、ref 解析不了、快照对不上都算应修；指向还没学的课算阻塞（剧透）。
- 地图数据（第 10 节「防剧透」）：这一天 build.json 的 `map` 和这一天用到的新地点（`places` 的 `label`、`kind`、`lore`）对照「禁止提及」，指向以后的内容算阻塞，归属 `planner`。
- 代码片段的行号（第 4 节「代码片段的出处和行号」）：摘自真实文件的代码块都带 `data-src`、`data-lines`；打开源文件逐行核对片段和行号，课文里的「第 N 行」落在片段显示的行号里。缺了算应修，行号和源文件对不上算阻塞。
- 多步演示（第 6 节）：自动播放时每一步的解说读得完、能单步、能暂停；做不到算应修。
- 媒介选择：有没有该用文字却做成动画（或反过来）的地方。

**严重度**：
- **阻塞**：事实错误、页面坏了（报错、MISSING、截断）、剧透、超时 >10%、画面和语音明显对不上。
- **应修**：讲解不清、例子不好、动画节奏不对、交互不直观、小测有歧义。
- **小问题**：措辞、样式细节。

**输出** `curriculum/<topic>/wNN/dN.review.md`，每条一行：

```
- [阻塞][writer] 位置：第 3 段第 2 自然段｜问题：……｜建议：……
- [应修][media:flow] 位置：beat "step2"｜问题：……｜建议：……
- [小问题][viz:token-cost] ……
```

归属标签：`writer`、`viz:<id>`、`media:<id>`、`planner`（地图数据：build.json 的 `map`、`places`）。复查时只看上一轮的阻塞和应修条目是否解决，在原条目后标 `✓ 已解决` 或 `✗ 仍存在`。

经验（随使用积累）：
- spec 本身也会错（代码跑不通、字面说法不成立、API 说法已经过时）。builder 按事实偏离 spec 时，以源文件和官方文档为准，不按 spec 原文判错；spec 里的错误在 review 里写明，由主会话转给 planner。

## 9. 返回给主会话的格式（所有 subagent）

主会话的输出用户会看到。所以返回内容**只写**：产出了哪些文件、数量、自测结果、已知问题（用归属和位置描述，不复述课程内容）。**不要**提未来周的任何内容，不要列出概念名称清单，**不要写小测答案**（哪个选项正确、参考答案内容）。

## 10. 迷雾地图的数据（planner 出，reviewer 查）

hub 的迷雾地图读 `site/map.json` 的 `topics.<topic>`。每个概念是图上的一个点；几个"是一回事"的概念合成一个**地点**（3D 地图上是一座峰或一处地标）；峰的高低是难度。planner 在 build.json 里出数据，主会话在 `/build-week` 第 4 步合进 map.json，reviewer 查剧透。有地点数据、浏览器画得了 3D 时 hub 用 3D 地图；map.json 没有 `places`（旧格式），或者浏览器没有 WebGL 2、显卡出错时，退回 2D 雾图，2D 只读概念的 `id`、`label`、`region`、`links`。

**字段**

| 字段 | 写法 | 谁出 |
|---|---|---|
| `regions[]` | `id`、`label`、`lanes`；可选 `home: { x, y, ext }`（区域在 3D 地图上的位置，不写时地图按区域出现的先后自己找位置） | planner；`home` 一般不写 |
| `moves` | 可选，`[[地点 id, 地点 id]]`：布局时两个地点换一次位 | 一般不写 |
| `places[]` | `id`、`label`、`region`；可选 `kind`、`lore`、`seed` | planner；`seed` 由主会话加（两座同种地标长得一样时） |
| `weeks[].days[].map[]` | `id`、`label`、`region`、`links`、`difficulty`、`place`；可选 `trap` | planner |

build.json 里，每天的 `map` 照上表写；这一周新出现的地点列在顶层 `places`，概念加进旧地点不用列。`place` 写在概念上，不写成地点的概念列表：概念按周加进来，合并时只追加，旧的不用改。

**难度**（`difficulty`，1–5 的整数）：按这位学习者的背景评（`learner/profile.md`），不按业内普遍的难度。
- 1：看一遍就懂
- 2：稍想一下就懂
- 3：要动手或要想一会儿
- 4：容易误解、要反复看
- 5：这个阶段最难、最容易卡住

**地点**（`place`）
- 一个概念只属于一个地点；一个地点里的概念在同一个区域。
- 按"这些是一回事、要一起理解"分，不按课分：一个地点可以跨几节课、几周，后来讲的概念可以加进旧地点。
- `id` 是 `p-<短名>`，整门课唯一；`label` 2–6 个字，学习者一眼认得。
- 地点只在它有概念的那一周进 map.json，不提前建。

**地标**（`kind`，不写就是峰）

| kind | 地标 | 什么样的地点 |
|---|---|---|
| 不写 | 峰 | 一处原理或事实 |
| `city` | 城 | 几样学过的东西拼成一个能跑的东西 |
| `canyon` | 峡谷 | 看着只是一道缝，里面还有一层看不见的过程 |
| `ferry` | 渡口 | 一来一回：发出去，再收回来 |
| `ruin` | 遗迹 | 来历：以前的事留下来的东西 |

- 拿不准就不写（峰）。
- 地标开放时至少 2 个概念。
- 每周新出现的地标 0–2 个；每种地标全图最多 3 个（每个主题每种地标只有 2 个样子，多了就重复）。
- 渡口要能放到江边；放不到时地图画成峰。
- 开放以后 `id`、`kind` 不再改（地标是按它画的，改了学习者熟悉的地方就变样）；`label` 只在 planner 明说改正时改。

**trap**：峡谷里"最容易掉进去的那个坑"，在那个概念上写 `"trap": true`；一个峡谷最多 2 个。别的地点不写。

**lore**：可选，一句 ≤40 字的"来历"，只用本周和已开放的内容。面板现在还不显示。

**地图自己算的**（不进数据）：地点的难度（= 里面最难的概念）、地点里概念的先后、学过没学过、地标的部件和样子、位置和地形、地点之间的路（由概念的 `links` 算）、焦点（下一节课第一个概念所在的地点）。所以数据里不写坐标，也不写地点的概念列表。

**合并**（`/build-week` 第 4 步、`/today`）
1. 每天的 `map` 原样合进 `weeks[].days[].map`（同一周整周替换），新字段跟着进去。
2. build.json 的 `places`：id 不在 map.json 里的追加到 `places` 末尾，已有的不动。
3. 新区域只会加在 `regions` 末尾；已有区域的顺序、`lanes`、`home` 不动。
4. 合完删掉没有概念的地点（`/today` 裁剪了课以后会出现；空地点本身就是线索）。
5. 跑 `node tools/map-check.mjs <topic>`，有错误让 planner 改 build.json 再合。

**防剧透**
- 概念的 `label`、地点的 `label`、`kind`、`lore` 开放时原样进学习者的网页：只用本周和已开放的内容，不留指向以后的线索。地点名不暗示后面会加进来什么；地标现在就要讲得通，不为以后的概念先占位。
- reviewer 对照 spec 的「禁止提及」查这一天的 `map` 和这一天用到的新地点：指向以后的内容算阻塞，归属 `planner`。
- 工作区是 git 仓库时，提交地图数据的提交信息只写周和计数，不写地点名和概念。

**检查**：`node tools/map-check.mjs <topic>` 查格式和前后一致：id、连线、区域、难度、地点、地标的限制、和上一次提交比已有地点的 `kind` 没变（工作区不是 git 仓库时不比）、只放 manifest 开放了的课。只打印计数和出错的 id，有错误时退出码 1。
- 还没开放的周：`--build curriculum/<topic>/wNN/build.json`，在内存里照上面的规则合进来再查，不写文件；这一周的 id 用位置代替（"w2 d3 第 2 个"、"places[7]"），开放前跑也不剧透。
- 改了规则或脚本：`node tools/map-check.mjs --self-test`。样例在 `tools/fixtures/map-check/`，用假的课，不放真实的课程内容。
- hub 本身（3D 地图的截图、退路、自检）：`node tools/qa-hub.mjs`，用法见文件开头。

## Decisions

改动重要规则时在这里记一笔：日期 + 改了什么 + 原因。下面是 v0.1 继承下来的设计决定。

- 「视频」做成页面里的配音动画（`seek(t)` 确定性渲染）：能拖动、倍速、逐 beat 截图审核，需要时用同一个 `seek(t)` 逐帧导出 mp4（`tools/render-video.mjs`）。
- TTS 按 beat 合成并按内容缓存；每个 beat 统一响度（目标 -16 dBFS + 限幅器），不同声音、对话之间不会忽大忽小。
- 视觉是"共用运行时 + 主题包"：`quest`（工程/编程）、`ink`（文科）、`anatomy`（数学/金融/理论）。不同学科适合不同的气质；侧边一直可见的今日路线让时间预算一直在眼前。
- 先猜再看、延迟检索（第 1 节）：只看不练容易以为自己学会了；先预测再看讲解（预测试效应）、隔几天再提取（延迟检索）都有研究支持。
- 先猜题在页面上标「先猜」、不占小测编号；选「还不确定」不算答错，显示中性的提示；events.mjs 把先猜和计分题分开算。原因：猜错和不确定都在预期之内，页面上要分得出哪道不计分，也不该让学习者看到"不对"。
- 「问老师」做题只给提示，学习者点「我试过了，看答案」或明确要求时才给答案，并记一笔（相关概念标"模糊"）；课末打卡有「讲给老师听」。原因：Bastani 等的对照实验里，直接给答案的 AI 让练习成绩变好、拿掉 AI 后考试变差，只给提示的没有这个损失；用自己的话讲一遍比再读一遍学得牢（自我解释效应，Chi 等 1994）。
- 课程页上提问只有「问老师」一个入口，由老师给每条回答归类（当场讲完 / 想深挖 / 周末问）：该不该现在问要看后面的课程安排，而路线图对学习者隐藏，这个判断本来就该老师做。
- 回指加回看（`<lh-recall>` + 生成时存的快照，第 4 节）：按固定 id 指向、生成时存快照，旧课改了或换了浏览器，看到的都是当时学的那一版；题目类先藏答案、热身题干不加回看，是为了先靠记忆回想。
- `data-min` 已经乘过 `pace_factor`：页面和 hub 上显示的分钟数是学习者实际要花的时间，才能据此决定几点开课。
- 2026-10-25：没有配音 key 时，字幕版默认用浏览器朗读（Web Speech API），播放器里可以关。原因：学习者想要免费的选项；不要 key、不要 ffmpeg，Edge 的在线声音能听，只是不如 MiniMax。按句读，时钟跟着读到哪句走。
- 2026-10-25：工作区默认 acceptEdits，第 1 节加「命令行」（改文件用 Edit、Write，Bash 只跑 `node tools/…`，不用 sleep）。原因：试装时生成课程会频繁要求确认命令，生成一周要几个小时，学习者不该一直守着；acceptEdits 只放行工作区里的改动，`.claude`、`.git` 和工作区以外的照样会问。
- 2026-10-26：hub 的迷雾地图换成拨云的 3D 地图，数据加地点、难度、地标（第 10 节）：概念加 `difficulty`、`place`、可选的 `trap`，map.json 加 `places`（可选 `kind`、`lore`）；合完跑 `tools/map-check.mjs`；reviewer 查地图数据的剧透，归属加 `planner`。原因：3D 地图用峰的高低表示难度，把"是一回事"的概念放进同一个地点，地标标出几种特别的地点；没有地点数据的老课程照旧显示 2D 雾图。地点名、地标开放时学习者就看得到，所以和概念一样只用已开放的内容；检查脚本只打计数和 id，开放前跑也不剧透。
- 2026-10-30：手写练习分清逻辑和语法（第 1 节、`CLAUDE.md`「做题只给提示」、`platform/ask-teacher.md`）：学习者说得清要做什么、只是不会写这门语言时，老师直接给那一处的写法，不算要答案、概念不降级；练习附语法速查卡，样板代码提前写好。原因：动手练习时，决定往往都做对了，时间却花在想语法上；目标是能读懂、能判断，手写时间留给逻辑。逻辑卡住仍只给提示。
- 2026-10-30：多步演示的节奏升成组件契约（第 6 节「多步演示」），reviewer 加一条检查（第 8 节）：能单步、能暂停，自动播放每步按解说字数留读的时间（1000 ms + 每字 100 ms，2–7 秒）。原因：几百毫秒换一次解说、不能单步的逐行演示，学习者看不过来，还以为自己没看懂。
- 2026-10-30：摘自真实文件的代码块标出文件名和原文件的行号（第 4 节「代码片段的出处和行号」，第 8 节加检查）。原因：课文按原文件的行号讲（「第 78 行」），页面上的片段只摘了几行、没有行号，学习者要自己数或者打开原文件才对得上。
