# 今日委托（quest）：Chlorophyll-Learn 视觉主题

## 适合的学科

工程、编程、工具类：这门课最核心的动作是"动手做东西"（写代码、搭系统、用工具）。人文阅读类用 `ink`，推导、建模类用 `anatomy`（见 `../README.md`）。

## 概念

每天的课是一张「今日委托」：左侧一直可见「委托目标」（今天的几段，读完一段菱形就变成金色）；页头的委托卡写着今天的标题、目标、时间分配和本课图鉴；小测是「挑战」；课末打卡就是「委托完成」，这是整页唯一一个编排好的庆祝动效。视觉语言借用现代二次元游戏 UI（干净明亮、细双线框、菱形标记、天青渐变配暖金点缀），但游戏感只放在页面边缘和结构上，正文栏不加框、不加装饰，30–55 分钟读下来也不累。适合喜欢有活力的现代游戏气质、靠"完成这一份"获得动力的学习者；每个进度都给出精确计数（3/8、2/3、用时 32 分钟）。

### 间距、圆角、阴影

- 宽屏版式：`--toc: 252px` 委托目标 + `--toc-gap: 64px` + 正文栏 36rem + `--gap: 3rem` + 右页边 `--side: 14rem`。段落编号菱形挂在正文左缘外 `--rail: 52px` 处（在 toc-gap 里）。
- 段与段之间 84px；委托卡内边距 46/44px；挑战、打卡框 24–32px。
- 圆角：框 `--r: 2px`（几乎直角）；按钮、筹码、底部按钮组、下载按钮用胶囊 `999px`。直角的框和胶囊按钮形成层级，不要统一成一种圆角。
- **双线框** = `border: 1px solid var(--line)` + `box-shadow: var(--frame)`（3px 留白 + 1px 外线）。需要浮起来的（委托卡、配音动画、打卡）再叠 `--lift: 0 22px 44px -30px rgba(26,107,158,.45)`：偏蓝的长阴影，不用灰色小阴影。
- **菱形**：8px 旋转 45° 的正方形，是整套设计唯一的图形母题。空心 = 未完成，金色实心 = 已完成，天青 = 正在进行，绿色虚线 = Stretch。

| token | 值 | 什么时候用 |
|---|---|---|
| `--t-fast` | .15s | 悬停 |
| `--t-mid` | .3s | 状态变化：目标变金、委托目标的当前标记滑动、图鉴收录 |
| `--ease-out` | `cubic-bezier(.2,.8,.2,1)` | 默认 |
| `--ease-back` | `cubic-bezier(.34,1.56,.64,1)` | 只给「委托完成」徽记 |

**委托完成**（约 1.7 秒，只在 `.lh-reward.celebrate`，即刚提交打卡时播放一次）：0–0.7s 金色菱形徽记弹出；0.2–1.1s 八道细金线向外放射；0.25–1.25s 六颗小菱形飞散；0.38s 对勾一笔画出；0.32–0.87s「委托完成」从左擦出，0.9s 一道高光扫过；0.6–1.25s 三格结算依次升起。`html.lh-still`（QA）和 `prefers-reduced-motion` 时直接画终点。除此之外页面没有自动播放的动效。

## 各元素怎么处理

- **顶部条** `.lh-top`：白色磨砂 + 底部双细线。`a.lh-back` 胶囊；`.lh-title` 隐藏（标题在委托卡上）；`.lh-track` 是正在读的目标（天青小菱形 + 得意黑 `3/8` + 段落标题）；`.lh-mini` 按分钟等比例（金 = 读过，天青 = 正在读，绿斜纹 = Stretch）；`.lh-clock`，超时 `.over` 变红加粗。
- **委托目标**（侧边今日路线 `nav.lh-toc`）：
  - 宽屏（≥1320px）：`main.lesson` 是两列 grid，`.lh-toc` 占左列所有行、`position: sticky`，一直在视口里（太长时自己滚动）。标题「委托目标 3/8」（得意黑 + 金色计数，前面一枚金菱形，下面双细线）。每条：编号在 26px 菱形里（`span.no`），标题最多两行（`span.t`），分钟在右（`span.m`）。菱形之间一条细竖线从这个中心连到下一个，这一段读过就变金。`li.seen` = 金色实心菱形 + 灰字；`li.now` = 天青菱形 + 加粗；Stretch = 绿色虚线菱形。当前段的 `.lh-toc-mark` 是一条从左边滑过来的天青光带（左边 2px 实线 + 渐隐底色），位置取 `.lh-toc-body` 上的 `--mark-y` / `--mark-h`。
  - 退路（<1320px，放不下侧边栏）：委托目标变成接在委托卡下面的白底双线框面板，两列排列（左列前一半、右列后一半，行数由 theme.js 写进 `--rows`），标题单行省略，当前段用天青渐变底标出；这时一直可见的是顶部条的 `.lh-track` 和 `.lh-mini`。<760px 变成一列。
- **委托卡**（`.lesson-head`）：白底双线框，左上、右下各一枚金菱形，框线上压墨蓝斜切标签「今日委托」（theme.js）。下半部分是两行"小标题 | 内容"（subgrid）：「时间分配」= 页头路线概览 `nav.lh-route` 画成一排按分钟等比例的细条，下面用 CSS 计数器标 1–8（和委托目标编号一致），再加一句"今天共 8 段，预计 30 分钟"；「本课图鉴 2/3」= theme.js 用 `api.codex` 生成的术语筹码，虚线空心 = 还没读到，白底实线 + 金菱形 = 已收录。**这里不再放目标清单**（委托目标在侧边）。
- **段落标题**（`h2 > span.n + span.ttl + span.rule + span.min`）：得意黑，下面一条双细线。`span.n` 挂在正文左缘外的菱形里，状态跟随 `section.is-now / .is-done`；`span.rule` 隐藏；`span.min` 靠右小字。≤1100px 时编号菱形回到标题前面。
- **正文**：不加框、不加底色。`dfn` = 天青粗体 + 前面一枚 6px 金菱形（和图鉴对应）；`mark` = 下半截暖黄荧光笔；列表符号是 6px 天青菱形。
- **一句话总结**：浅金底 + 左边 3px 金线，不加图标。
- **🔭 后面会讲**（`aside.later > span.tag > span.emo`）：右页边，上方一条蓝色细线带空心菱形，标签蓝色粗体，正文蓝灰。🧗 Stretch 同样处理，绿色。≤1100px 收进正文，变成白底卡片 + 左边 3px 色线。
- **小测 = 挑战**：白底双线框，框线上压墨蓝标签 `.lh-qlabel`「挑战 2/6」或「回想挑战」，标签前的小菱形：未答浅青、`.is-right` 金、`.is-wrong` 灰。选项是浅底长条，字母在菱形徽记里；答对 = 绿框 + 绿色实心菱形，答错 = 红框 + 删除线；判定行带 ✓ / × 圆标。解析是浅蓝底 + 左边天青线。
- **代码块**：白底细框，左边 3px 天青线，复制按钮是悬停才出现的胶囊。
- **表格**：白底细框，表头浅蓝底 + 天青字，第一列加粗且不在词中间断开。
- **插槽说明**（figcaption）：`span.kind` 是墨蓝斜切小标签（配音动画 / 交互），`span.ttl` 加粗，`span.dur` 天青数字，`span.hint` 另起一行。
- **按钮**：主按钮 = 墨蓝胶囊 + 内圈细线（悬停时内圈变金）；次按钮 = 白底胶囊 + 细描边。选中的筹码（难度、哪几段有帮助）= 主按钮样式；难度的数字 `span.key` 用得意黑，选中后变金。
- **课末打卡 / 委托完成**：表单在白底双线框里；结算 `.lh-done` = 徽记（theme.js 画进 `.lh-emblem`：双线金菱形 + 对勾 + 8 道光线 + 6 颗小菱形）+ 得意黑大字「委托完成」+ 三格 `dl.lh-stats`（目标 x/8、用时、图鉴 x/3）+ 浅金底的 `p.lh-done-msg`；完成后框的左上角也有一枚金菱形。
- **右下角三个按钮**：白色胶囊按钮组，双线；选中文字时浮出的 `.floating` 版本是墨蓝底。弹窗白底双线框 + 左上金菱形；提示条墨蓝胶囊 + 金色内圈。
- **播放器**：舞台上方两角各一枚金菱形；字幕和控制条是同一种深色磨砂 HUD（`rgba(20,32,56,.78~.86)`），在明亮舞台和旧的深色舞台上都清楚。进度条上的 beat 刻度是小菱形，播放头是金菱形；开始/重播按钮 `button.lh-big > span.ico + span.t` 是墨蓝胶囊 + 金色圆形播放钮 + 淡色时长；`a.lh-dl`（导出过 mp4 才有）是细描边胶囊，前面一颗小金菱形。

## 配音动画的画法（media agent）

**参考实现**：`/lab/themes/quest/media/one-request/scene.html`（直接照着它的配色常量 `C`、状态写法和封面写）。

- 舞台 1280×720，底：`radial-gradient(ellipse at 50% 30%, #FFFFFF, #EEF6FC 48%, #DDECF7)`，可以加 32px 浅点阵和一两条白色细同心圆做氛围（透明度低，不抢内容）。
- 配色（和 player.css 的 `--lh-*` 一致）：面板 `#FFFFFF`，次级面板 `#F1F7FC`，未激活描边 `#B6CADC`，主色 `#1F7EC2`，光晕 `#58B4E8`，标题字 `#142038`，正文字 `#22324D`，次要字 `#5A6D88`，成功 `#17845A`，警示 `#B9521A`，暖金 `#E2A631`（金色文字用 `#946609`），核心物件深底 `#1B2E55`。也可以直接用契约 token（`var(--ink)` 等）。
- 三种状态：**未知** = 白底 + 虚线描边 + "?"；**已命名** = 白底 + 主色描边 + 深色字；**点亮** = 主色填充 + 白字 + 光晕。一次只点亮一个，其余用透明度压暗（0.32 左右）。深色的核心物件压暗会发灰，透明度下限放到 0.7 以上。
- 暖金每个画面只用在一处：核心物件（比如"模型"）的内圈细线和顶上的小菱形、封面副标题两侧的菱形。
- 封面：得意黑大标题（`class="disp"`，`svg text.disp { font-family: var(--lh-display) }`，字重 400）+ 一行副标题，两侧细线 + 金菱形。
- 画面文字 ≥28 单位，正文用 `var(--lh-font)`；底部 15% 留给字幕和控制条。字幕不用自己画；第二个声音自动显示金色 + 菱形标记。
- 旧的深色场景（比如真实 Day 0 那一个）在这个主题下也能用：深色 HUD 控制条两种舞台都适配。新做的场景一律用明亮舞台。

## 交互组件的画法（viz agent）

**参考实现**：`/lab/themes/quest/viz/reliability.html`（菱形格子、大数字、面板、挑战框的写法都在里面）。

- 只用 component.css 的变量。白底；需要分区时用 `.panel`（浅底双线框），面板最多嵌套一层。
- 关键数字用得意黑（`.num` 或 `font-family: var(--display)`，字重 400），控件读数用天青色得意黑。
- 计数类图形（100 个请求、N 个样本）用**菱形格子**：`<rect transform="rotate(45)">`，填充 `--mint`（正确）/ `--red`（静默出错）/ `--amber`（被发现），里面再画 ✓ × ! 区分形状，照顾色弱。
- 按钮是胶囊；预设、分段选择用 `aria-pressed="true"`，自动变成墨蓝 + 金色内圈。滑块是天青轨道 + 金色菱形滑块（运行时把当前比例写进 `--fill`，不用自己处理）。
- 组件里的小挑战：虚线框 + 空心菱形，完成后变成金色实心菱形 + 金底「挑战完成」斜切标签，和委托目标同一个逻辑。
- 画布舞台用 `--screen`（明亮），不要再画深色背景。

## Do

- 把游戏感放在结构上：框、标签、菱形状态、委托目标、进度计数。
- 每个进度都给精确数字（3/8、2/3、32 分钟）。
- 状态用"空心 → 金色实心"的菱形表达，全站一个逻辑。
- 金色当奖励用：已完成、终点、唯一的庆祝。
- 正文保持安静：白纸黑字，最多一处荧光笔，一个一句话总结。
- 颜色之外再用形状区分状态（✓ × !、实心 / 空心 / 虚线）。

## Don't

- 不用任何游戏的角色、logo、名字、字体或图标；不做羊皮纸、像素风、中世纪纹样，不放彩带和 emoji 庆祝。
- 不给正文段落加框、加底色、加装饰菱形；不在正文里用得意黑排长段文字（它是斜体展示字）。
- 不加英文全大写小标签（如 QUEST、MISSION）。游戏词汇只用这五个：今日委托、委托目标、本课图鉴、挑战、委托完成；其余沿用平台原有叫法（打卡、后面会讲、Stretch）。
- 不加第二个自动动效（进场动画、悬停放大卡片、循环发光）。
- 不把金色当文字色（对比度不够，用 `--gold-ink`）。
- 不把 🔭 做成"未解锁图鉴"去收集：那会把以后才学的名词变成收集目标，鼓励过早深挖。

## 设计取舍（相对最初提案）

1. **🔭 不进图鉴**：图鉴只收录本课的 `<dfn>`。很多学习者容易急于深挖，把以后才学的名词做成待收集项正好会刺激这一点。
2. **庆祝克制**：细金线 + 六颗小菱形 + 一道高光，1.7 秒结束，不用彩带、星星、音效。
3. **游戏词汇限定五个**，其余沿用平台原有说法，课程页里对"蓝色 🔭、绿色 🧗、右下角三个按钮、课末打卡"的描述依然成立。
4. **侧边委托目标取代了正文左边的路线竖线**：原方案在正文左缘画了一条串起各段的竖线；有了一直可见的委托目标后，两条路线并排会重复，所以只留段落编号菱形。
5. **配音动画用明亮舞台**，和 style-guide 早期"深色屏幕"的约定不同：为了和"干净明亮"一致；字幕和控制条用深色 HUD 保证对比度（也让旧的深色场景能直接用）。
