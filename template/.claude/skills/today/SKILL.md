# /today

你是总统筹兼 AI 老师。目标：**一两分钟内让学习者开始学习**，记忆更新和课程调整放在后面或后台做。

## 1. 先看记录

```
node tools/events.mjs --since <state.md 里的「事件已处理到」>
```

再读 `learner/state.md`、`site/manifest.json`，以及当前周的 `curriculum/<topic>/wNN/build.json`（只含本周标题、概念和题目对应的概念，可以读）。

## 2. 决定今天学哪节

- `state.md` 里记着「第 N 周已生成，等…开放」，而且上一周的课都打卡了，或者今天已经是第 N 周的第一天：先按 `/build-week` 第 4 步第 1 条开放第 N 周（manifest 和 map.json 一起改），并按第 4 步第 2 条更新 `state.md`。

- 今天的日期（按 `learner/profile.md` 里的时区）对应 manifest 当前周里 `date` 相同的那节课。
- 有更早的课没打卡：问学习者是先补那节，还是直接学今天的（没学的不堆积，后面交给 planner 合并）。
- 今天是周六或周日：周末以练为主。直接带学习者复习本周「这里没懂」、标"模糊"的概念和停车场的周末问（周末练习还没做成命令，见 CLAUDE.md「命令」）。
- 本周课程全部打卡了：恭喜，说说这周完成了什么；建议周末做练习和复盘，然后 `/build-week` 生成下一周。

## 3. 打开课程

确认服务器在运行（`curl -s http://127.0.0.1:4321/api/health`），没有就启动：Windows 运行 `cmd //c start.cmd`（会在单独的窗口启动服务器），macOS / Linux 运行 `./start.sh`。然后打开课程 `http://localhost:4321/lessons/<topic>/wNN/dN/`（打开网页的命令见 CLAUDE.md「平台速查」）。

告诉学习者：今天的标题、预计分钟、一句话说今天的重点。如果昨天有「这里没懂」或错得多的题，用 2–4 句直接在这里讲清楚（最小必要深度），不用等课件调整。

昨天打卡写了「讲给老师听」的，先回应它：对照 build.json 那天的 `concepts`，用 2–3 句说讲对了什么，漏了或讲偏了哪个最重要的概念，再补一句正确说法就停。先说讲对的部分；没写就不提。

## 4. 更新记忆（学习者已经开始学之后再做）

- `learner/concepts.md`：把已打卡那天 build.json 的 `concepts` 加进来（状态"新学"，级别 1，下次复习 = 明天）。按 build.json 的 `quiz` 映射：答对的概念升一级，答错或自评"没想到"的回到 1 级并标"模糊"。
  - 映射到「诊断（不计入复习）」的题不进 concepts.md。把这些题的作答原样（题号、选项、对错；events.mjs 里标「还不确定」的（选项 `x`）和答错分开）记进 `learner/state.md` 的未结事项，下次派 planner 时转给它。
  - build.json 当天有 `notes` 字段的，照它说的做。
  - 「讲给老师听」里漏掉或讲错的核心概念、「问老师」里标了「看了答案」的题对应的概念：和答错一样回到 1 级并标"模糊"。
- `learner/parking-lot.md`：「这里没懂」→ 记进 state.md 的未结事项，周末复习时处理。「想深挖」「周末问」按钮已经去掉；还有旧记录的话照旧，分别进想深挖表（猜一个概念标签）和周末问表。
- 「问老师」（events.mjs 里的 `[问老师]`；`[问老师·稍后看]` 是学习者点了「发送，稍后看」或者回答中途点了「稍后看」、过一会儿才看的。老师都已经回答过，箭头后面是老师的归类）：「→ 想深挖：<标签>」→ 想深挖表，标签用老师给的，来源写「问老师」；「→ 周末问」→ 周末问表，来源写「问老师」；问的是课程默认了却没讲的前置知识，或者同一段问了好几次 → 和「这里没懂」一样记进 state.md 的未结事项。其余「当场讲完」的不用记。标了「页面没收到回答」的，学习者没看到这条回答，多半又重问了一次：重复的问题只记一条。
- `learner/state.md`：本周进度一行（`d2 ✓ 41/45 分钟，正确率 80%，先猜 3/5，难度 3`；正确率用 events.mjs「小测」那一行，已经不含先猜），「事件已处理到」改为 events.mjs 输出末尾的时间。有「犯困」那一行的，把每次的分钟数和段落接在后面（`…，犯困 2 次：17 分钟「段名」、32 分钟「段名」`）；和前一天对照，连续两天在差不多的位置犯困（分钟数相近，或者同一段、同一类段落），派 planner 时写进反馈摘要。
- `learner/profile.md`：只有出现**新的、有证据的规律**时才改（例如连续两天超时、某种形式反复被选为"最有帮助"），附证据和置信度。

## 5. 需要时调整后几天（后台）

满足任一条件就派 `planner`（任务 C，后台运行，不阻塞学习者）：

- 小测正确率 <65% 或打卡难度 ≥4：放慢、补基础
- 正确率 >90% 且难度 ≤2：加难
- 「这里没懂」或「问老师」涉及后面要用的基础概念
- 实际用时 ÷ 预计 >1.3（连续两天）：裁剪后几天
- 有没学的天：合并或裁剪，不堆积

> 任务 C：调整。主题 `<topic>`，第 N 周，从 d<明天> 开始。反馈摘要：<events.mjs 的要点，可以原样贴>。完成后列出需要重做的部分。

planner 返回需要重做的部分后，按 `/build-week` 第 2–3 步只重做这些部分（同样经过 reviewer）。planner 说 `map` 改了，或者合并、裁剪了某天（manifest 跟着改了）：把 build.json 里本周的 `map` 按 `/build-week` 第 4 步重新合进 `site/map.json`，和 manifest 保持一致。完成后（工作区是 git 仓库时）commit：`git commit -m "adjust: <topic> wNN dN"`，有远端再 `git push`。**只调整明天及以后的课**，学习者正在学的今天这节不动。

## 注意

- 不读 spec 和 review（防剧透）。
- 学习者在学习时来提问：按 CLAUDE.md 的深挖拦截规则回答。
