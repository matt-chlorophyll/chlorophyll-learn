# /new-topic $ARGUMENTS

你是总统筹兼 AI 老师。学习者想开始学「$ARGUMENTS」。

## 1. 访谈（最多 2 轮 AskUserQuestion，每轮 ≤4 个问题）

目的是让 planner 知道起点和目标，不是填表。已经在 `learner/profile.md` 里的信息不要再问。必问：

- 对这个领域熟悉吗（完全陌生 / 了解一些概念 / 有实际经验）
- 相关基础：学这个主题通常要用到的前置知识，学习者有多少（例：学编程问会哪门语言、写过多少代码；学金融问数学和统计基础；学历史问读过哪些书）
- 用过哪些相关的工具或资料
- 学这个最想用在哪里（工作中的具体场景 / 自己的项目 / 换工作 / 考试 / 单纯想懂）
- 周末动手练习用什么（按主题问：写代码要不要 API key、做题要不要纸笔、要不要真实数据）

`profile.md` 的「节奏与时长」还空着时（第一次用这个平台），同一轮里再问：

- 时区，工作日通常几点开始学、每天最多学多久（默认 55 分钟）

- 视觉主题：按学科推荐一个，放进同一轮问卷让学习者确认（推荐项放第一个并标「推荐」，选项说明里附样例页 http://localhost:4321/lab/themes/<主题>/）。工程、编程、工具类 → `quest` 今日委托；文科（历史、文学、哲学、艺术、语言）→ `ink` 水墨；数学、金融、物理、理论类 → `anatomy` 图谱。各主题的气质见 `site/assets/themes/README.md`。样例页需要本地服务器在运行（没有就先启动，见 CLAUDE.md「平台速查」）。

回答里有模糊的地方，用一两句话追问，不要再开一轮问卷。

## 2. 写记忆

- 主题 slug：英文小写加连字符（如 `ai-engineer`、`macroeconomics`）。
- 改写 `learner/profile.md` 的「目标」「背景」（标注"自述，<日期>"），第一次用时连同「基本情况」「节奏与时长」一起填。
- 改写 `learner/state.md`：主题、slug、视觉主题、当前状态、下一步（`/build-week` 第一次把这门课加进 manifest 时会写上 `theme`）。

## 3. 路线图

派 `planner`：

> 任务 A：新主题路线图。主题：$ARGUMENTS，slug `<topic>`。访谈摘要：<3–6 条要点>。写 `curriculum/<topic>/_roadmap.md`，完成后按约定返回。

## 4. 第一批课程

- **陌生或只了解一些**：运行 `/build-week 0` 的流程生成 **Day 0 导览课**。要求（写进给 planner 的任务 B 里）：≤30 分钟；让学习者快速看到这个领域的全景和底层逻辑（它为什么存在、核心机制、这个领域的人每天在做什么或者学会以后能做什么）；简短介绍平台怎么用（🔭、🧗、「问老师」和「这里没懂」、打卡）；结尾有一组诊断小测，用来校准起点（题目覆盖不同难度，答错不扣面子）。
- **已经有实际经验**：跳过 Day 0，告诉学习者运行 `/build-week 1`（周末跑最合适：完整档约 3–4 小时；赶时间可以 `/build-week 1 lite`）。

## 5. 告诉学习者

已经准备好了什么、怎么打开（Windows 双击 `start.cmd`，macOS / Linux 运行 `./start.sh`，或者在这里运行 `/today`）、学完 Day 0 后需要的反馈（打卡表单 + 在这里聊几句对形式的感受）。不透露路线图。
